# Meezan Builders — Real Estate & Business Management System

A local Flask application for managing property inventory, client preferences, sales leads, follow-ups, and simple property matching. This initial version is a **local prototype**. It has no user authentication or role-based authorization and must not be exposed publicly or used to store sensitive customer data.

All listings and people created through the optional demo command are fictional. The application starts with an empty database.

## Features

- Dashboard totals sourced from SQLite, recent property listings, and due follow-ups.
- Property create, view, edit, and delete, with search and status/type/location/price filters.
- PKR, Thousand, Lakh, Million, Crore, and Billion price entry; final prices are converted with `Decimal` and stored in the integer `price_pkr` column.
- Multiple property images with content/format checks, per-image size/pixel limits, previews, galleries, and explicit removal.
- Client directory, profiles, preferences, and CRUD operations.
- Lead creation and updates, status tracking, notes, and follow-up scheduling.
- Overdue/upcoming follow-up view.
- Preference-based property matching using available listings.
- Optional fictional demo dataset via a Flask CLI command.

## Technology

- Python 3
- Flask and Jinja2
- SQLite
- HTML, CSS, and vanilla JavaScript
- Flask-WTF CSRF protection and Pillow image verification

## Setup

Requires Python 3.9 or newer.

1. Create and activate a virtual environment from the project directory:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

2. Install the application dependencies:

   ```powershell
   python -m pip install -r requirements.txt
   ```

3. Optionally set a private Flask signing key for local use:

   ```powershell
   $env:FLASK_SECRET_KEY = "replace-with-a-long-random-local-value"
   ```

The default SQLite database is created at `data/real_estate.db` automatically when the application starts. Before changing an older schema, the app creates a timestamped `*.backup-*` next to the database using SQLite's backup API. Existing prices are treated as already being PKR: they are copied to the integer normalized-price column without applying a unit multiplier. Original `price` and `image_path` columns remain for compatibility. Legacy fractional price values are marked for review, displayed as unverified, and excluded from property matching; editing other fields without changing that amount preserves it. Review the original listing and choose the intended unit explicitly if you want to normalize a flagged legacy amount. Valid existing image files are migrated to the image gallery; missing files are not rendered as broken links.

To use another database location, set the `DATABASE` environment variable before starting the app.

`MAX_IMAGE_BYTES` limits an individual image to 5 MiB by default; `MAX_UPLOAD_TOTAL_BYTES` limits the whole request to 25 MiB. Set either environment variable to a different positive byte limit if required. Pillow checks actual image format and dimensions; filenames are generated by the application and never used as storage paths.

## Run locally

```powershell
python app.py
```

Then open <http://127.0.0.1:5000>. Debug mode is disabled unless `FLASK_DEBUG=1` is explicitly set. Only run the development server on a trusted local machine.

## Optional fictional demo data

After installing Flask, load one small fictional property, client, and lead:

```powershell
flask --app app demo-data
```

The command refuses to add another copy when the demo client already exists. Remove the local test/demo records through the application if no longer needed; do not distribute the local database.

## Tests

Run the standard-library test suite:

```powershell
python -m unittest discover -s tests -v
```

Each test uses a temporary SQLite database and temporary upload directory and does not use the default application database. Coverage includes edits with/without replacement images, multiple image uploads, image preservation/removal and rejection, PKR unit conversions, legacy migration, CSRF handling, matching, and existing CRUD flows.

## Limitations and future improvements

- This version has no login, authorization, or audit trail. CSRF tokens protect browser POST requests, but this is not a substitute for authentication or authorization. Keep it bound to localhost; do not expose it to the internet or treat it as production-ready.
- The local prototype has no automated backups, deployment configuration, or production security review.
- Image verification is not a substitute for malware scanning.
- Matching requires a compatible size unit and matches all populated preferences; it does not convert between marla, kanal, or square feet.
- Future work could add authentication and roles, stronger contact validation, image processing, pagination, audit history, and deployment hardening.
